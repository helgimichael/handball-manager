# Canonical career diagnostics

Final delivery evidence is in `DELIVERY.md` and `verification/`. The fifty-match sample and two independent repeats used fixed source bytes. The later unused-import/compatibility-comment lint cleanup has byte-identical emitted JavaScript, recorded in `release-source-equivalence.json`; do not overwrite historical sample fingerprints to conceal this source-only change. Full truth hashes remain the canonical result/continuation proof.

The benchmark calls the actual player-match path: `createNewCareerState` with the repository's real squad/rating snapshots, then `startProductionMatch`, repeated `advanceProductionMatch`, and `resultFromSession`. It does not call the legacy QA `simulateMatch`, the fast background engine, the synthetic V2 `runMatch` or Motion. Render frames are captured by production itself.

Baseline and after use the same 50 fixed save seeds and first actual league fixture for rotating Allsvenskan manager clubs. Seed recipes, actual canonical numerical seeds, fixture identities, selected player IDs, initial profiles/energy, recorded shots/locations and canonical ledger possession endings are retained. CPU substitution/timeout logic remains the actual opponent policy; the manager starts with the unchanged normal default plan. These are independent full-match inputs, not a career-season longitudinal sample.

The `inputs.json` snapshot pins real world squads and gameplay ratings. Generated career fallback attributes remain generated by the existing deterministic career constructor for the exact save seed. The SHA-256 input hash is checked before producing a paired comparison. Baseline source fingerprints retain all non-test V2 core files and the production bridge, including pre-existing uncommitted engine work.

Run from `apps/game`:

```powershell
node --import tsx scripts/match-realism-benchmark.ts --count 50 --out ../../docs/match-realism-v2/baseline
node --import tsx scripts/match-realism-benchmark.ts --count 50 --inputs ../../docs/match-realism-v2/baseline/inputs.json --out ../../docs/match-realism-v2/after
```

For one recorded match use `--count 1 --offset INDEX --inputs ...` and an isolated output directory. `--offset` retains the original seed/manager selection recipe. Do not overwrite the recorded baseline. Runtime logs go in `.tmp` rather than the player interface.

The pilot measured about 6.6–6.9 seconds for a full canonical simulation and about 10.2 seconds total per case including career construction and detailed diagnostic reading. That made 50 matches practical. Formal baseline/after runtime distributions are reported independently; they include production frame capture and its state cloning, not only a bare engine tick loop.

## Measurement definitions

- **Possessions:** canonical ledger attacks with a live touch. Procedural dead-ball fragments are excluded. Ownership comes from the ledger.
- **Duration:** first-to-last recorded event span in official time, with stopped time excluded; simulation span is also retained. It is not a newly invented lifecycle.
- **Passes:** canonical PASS_RELEASED / PASS_RECEIVED counts, including legal restart deliveries represented as passes. Completed pass count by possession is in the ledger.
- **Turnovers:** canonical `nonShotLoss` counts attacks lost without any shot. `turnoverEndings` mirrors career result classification by `lossClassOf`; it can include an earlier shot followed by loss. Both definitions are explicit.
- **Shots:** actual SHOT_RELEASED events. Categories are existing V2 BACKCOURT_JUMP, STANDING, BREAKTHROUGH, WING, PIVOT, SEVEN_METRE and EMPTY_GOAL when observed. Geometry uses recorded release positions and actual period-start/end direction.
- **Shooter positions:** paired `role`/`shooterPositions` uses immutable MatchPerson identity/initial position (starter selected slot or bench original role). Post-baseline `tacticalRole` additionally follows chronological EXCHANGE_COMPLETED role assignments. A CPU replacement can occupy another role, so those two counts must not be conflated.
- **Goalkeeper saves:** SAVE_CAUGHT / SAVE_PARRY. Save percentage is saves/(saves+goals); all-attempt save share is also reported. A physical parry/rebound sequence remains represented by its actual events.
- **Transition:** actual phase-bearing events and transition shot releases. An exact count of all transition attempts without a phase-bearing event is unavailable in the baseline.
- **Scorer concentration:** top scorer share and the sum of squared scorer goal shares (HHI), computed per team then averaged per match. Real player IDs and contribution counts remain available.
- **Distributions:** mean, median, linearly interpolated p10/p90, minimum and maximum. Per-match distributions and pooled possession/shot-unit distributions have separate denominators.

Unavailable fields describe the recorded benchmark schema. They do not mean V2 cannot be instrumented further. In particular, the baseline did not preserve a separate first-threat classifier; first release latency is stored, and action-level causal windows were added after the baseline. Exact transition attempts lacking a phase-bearing event are not counted by this event-only reader.

## Existing references and attribution

`packages/handball-engine/src/v2/core/realism.ts` contains the existing EHF_ELITE profile. Its header explicitly calls these broad plausibility intervals rather than historical statistics. The October 7 audit likewise states the intervals are development assumptions and its six synthetic matches are not league calibration. This task labels them accordingly. No exact empirical target is invented for duration, scorer concentration, save rate or transition attempts.

The production bridge consumes the game's actual gameplay rating branch. `core/profile.ts` maps Handball Manager's 1–20 keys to distinct passing, handling, power/placement, breakthrough, finishing, wing/pivot, decision/reading, movement, defensive, physical and goalkeeper capacities. Benchmark initial profiles retain the exact consumed capacities and source-completeness record for every actual player. They are diagnostics only; no CA/PA is shown to the player.

Every aggregate preserves outliers and interval breaches. A statistically acceptable score alone is insufficient: representative browser matches must still be inspected for the attack → pressure/help → available continuation → outcome relationship.

The post-baseline harness additionally retains small first-occurrence causal event/frame windows for gap attacks, defensive reactions, intended pivot/wing passes, loss, save, settled handoff and contact. These are actual recorded chronological windows with the original event reasons and quantized production frames. They do not stage a play or claim that an intended pass succeeded. If a named anchor never occurred it is explicitly absent. Shot-release details are retained intact for newer execution/decision trace fields. This evidence stays in developer tooling and does not add debug noise to normal career archives.

The paired comparison automatically proposes a representative match nearest the joint sample medians, the naturally closest remaining match and the highest-scoring remaining match. The selection recipe and exact save/fixture/canonical seeds are written to `human-qa-matches.json`; it never filters out undesirable matches.
