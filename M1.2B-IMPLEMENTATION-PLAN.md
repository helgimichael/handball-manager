# M1.2B implementation plan

Proposal only, 2026-11-07. M1.2A ends with these reports. Nothing below is implemented or authorized for deployment.

## Smallest viable scope

Deliver a versioned Swedish rule package for all four requested leagues, its validator and a **read-only transition preview**. Adapt existing tables/ties as inputs without changing active progression. This is useful immediately: it exposes exactly why a proposed next season is or is not supported.

Do not turn on the new live rollover in M1.2B. The baseline's Division 1 strength ranking cannot satisfy official rank selectors; adding a new automatic promotion path on top would preserve fabricated qualification inputs. Subsequent runtime integration needs the dependencies below.

Likely integration area: `apps/game/lib/competition/`, with career membership/save adapters. Keep the country package separate from generic graph/planning logic. No new service, database or match-engine package is needed. Final module names can follow repository conventions during implementation.

## Meaningful verification for that implementation

- Validate exact Swedish slot coverage, cross-group feeds and home reference semantics; include Norra's shared final so independent-swap assumptions fail.
- Exercise eligible replacements, refusal, unknown/terminated A/B agreements, licensing appeal/capacity exception and exhausted vacancy inputs.
- Show an otherwise complete top-tier season remains blocked by missing Division 1 ranks; show unknown Division 2 entrants remain unresolved without changing club counts.
- Verify neutral sporting tiebreak requirements stay unresolved instead of using club ID/hash; cover ambiguous multiway ties.
- Check canonical-ID uniqueness, one membership per club, conflicting claims, geographic allocation, unsupported odd counts and exact fixture coverage readiness.
- Confirm preview repeatability and non-mutation, including squads/ratings. Existing midseason/legacy outcomes must not be rewritten or silently certified.
- Run focused new competition tests and existing competition/save regressions, then repository typecheck/lint as appropriate. Store any QA logs/reports under `C:\DEV\QA\logs\` / `C:\DEV\QA\reports\` per filesystem policy.

## Gates before a later live rollout

| Dependency | Required resolution |
| --- | --- |
| Division 1 sporting inputs | Simulate both real groups fully in the background, or introduce evidenced external table/result input. Manager playability can remain restricted independently. |
| Lower-pyramid boundary | Supply verified real entrants/outcomes and destinations when needed; otherwise retain a blocked transition with a visible reason. No Division 2 fabrication. |
| Eligibility evidence | Verify season-specific registered cooperation agreements, their dates/termination, licence decisions and entry acceptance. Existing permanent game links are not sufficient legal evidence. |
| Remaining rule details | Confirm northern Y semi-off home reference, series terminal-decider selection, complex ties and current official date plan. Match-engine changes require a separate milestone if fidelity demands them. |
| Geographic allocation | Supply an explicit allocation decision/provider. Replace arrival/ID balancing and the manager exemption only in a later authorized runtime change. |
| Future seasons / manager below coverage | Choose and label inherited fictional rules versus verified-season mode; decide supported career behavior when the manager's club leaves coverage. Preserve actual outcome and save. |
| Atomic rollover / compatibility | Integrate preview into a validated, idempotent transition; archive all source groups, use final memberships for fixtures, and preserve legacy saves under a pinned legacy profile. |

Do not bundle cup redesign, ratings recalibration, economy retuning, club-ID migration, new countries, full Division 2 authoring or changes to regulation-time simulation into M1.2B.
